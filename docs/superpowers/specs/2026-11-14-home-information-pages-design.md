# Дизайн: главная и информационные страницы магазина

## Цель

Довести главную страницу и разделы «О магазине», «Качество», «Доставка и самовывоз», «Рецепты» до состояния понятного коммерческого сайта, сохранив текущий каталог, навигацию и безопасную границу подтверждённых данных.

## Что входит

- Главная: выразительный первый экран, шесть категорий, отдельные акценты для полуфабрикатов и национальной продукции, безопасный блок популярных товаров, доверие и контакты.
- Информационные страницы: содержательная структура с ясными пустыми состояниями там, где нет подтверждённых текстов, фотографий, документов или рецептов.
- Рецепты: типы данных и маршруты-подготовка для будущих материалов без публикации выдуманных рецептов.
- Адаптивность, клавиатурный фокус, единые header/footer и текущие SEO-маршруты.

## Не входит

Реальный ассортимент, цены, фото, сертификаты, отзывы, график работы, тарифы и зона доставки; Supabase, админ-панель, корзина, оплата и изменение архитектуры каталога.

## Подходы

1. **Расширение текущей системы — выбранный подход.** Сохранить существующие маршруты и классы, вынести безопасный контент в отдельный слой данных, добавить небольшие переиспользуемые секции и условный блок товаров. Риск регрессий минимален.
2. Полная перестройка визуального слоя. Даёт больше свободы, но неоправданно затрагивает общую дизайн-систему и рабочие маршруты.
3. Заполнить страницы реалистичными примерами. Не допускается правилами проекта, так как подтверждённых материалов нет.

## Визуальное решение

Сохраняется палитра cream / graphite / terracotta / sage и пара display-сериф + нейтральный sans-serif. Главная получает один характерный приём: контрастные «витринные» панели с крупной типографикой и спокойными информационными карточками, а не повторяющиеся одинаковые блоки. Placeholder-media остаётся только как явно обозначенное место для будущего подтверждённого фото.

## Контентная модель

Каталог продолжает читать `products` из текущего источника. Популярный блок рендерит карточки только для продуктов с тегом `popular`; при пустом массиве показывает не пустые товарные карточки, а объясняющее состояние. Рецепты получают поля категории, ингредиентов, шагов и связанных product slugs, но текущий опубликованный массив остаётся пустым.

## Проверка

Выполнить `npm run build` при отсутствии `.next/types`, затем `npm run typecheck`, `npm run lint`, `npm test`, повторный `npm run build`, `git diff --check`, локально проверить все страницы и переходы на desktop/mobile. После коммита — push feature-ветки, запуск/проверка Pages только при наличии workflow или явной доступной публикации, затем проверить публичные URL.
