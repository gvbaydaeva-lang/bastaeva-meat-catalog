# Подготовка каталога к наполнению ассортиментом

## Назначение

Подготовить безопасный и повторяемый способ добавлять подтверждённые товары в статический каталог ИП Бастаева А.Д. через Codex, не публикуя тестовые или неподтверждённые позиции.

## Цели

- Сохранить существующие маршруты, дизайн, поиск, фильтры, SEO и пустые состояния.
- Хранить товар в едином каноническом JSON-источнике, который импортируется в `lib/data.ts`.
- Поддержать CSV для массовой передачи данных и JSON для сложных полей.
- Поддержать одну или несколько ценовых опций с единицей продажи.
- Проверять обязательные поля, уникальность slug и названия, связи категории/подкатегории, цены, единицы продажи и существование файлов фотографий.
- Подготовить структуру папок фотографий без добавления реальных изображений.
- Проверять импорт на отдельной тестовой фикстуре, не подключённой к сайту.

## Не входит в задачу

- Добавление реального ассортимента, цен, наличия, состава или фотографий.
- Админ-панель, Supabase, корзина, онлайн-оплата и загрузка файлов через сайт.
- Изменение визуального оформления и публичной информационной архитектуры.

## Подходы

1. Канонический JSON и CSV-адаптер с общим валидатором — выбранный вариант. Он сохраняет типобезопасность JSON и даёт удобный табличный формат для массовой подготовки.
2. Только CSV — проще для таблиц, но неудобен для нескольких цен и списков фотографий/назначений.
3. Только JSON — строгий формат, но менее удобен для передачи длинного списка товаров.

## Решение

Канонический файл `data/catalog-products.json` будет оставаться пустым до отдельного задания. Поля товара включают название, slug, категорию, подкатегорию, описание, состав, назначение, наличие, фотографии, характеристики и `priceOptions`. Для обратной совместимости существующий `price` будет вычисляться из первой ценовой опции, если она есть.

Импортёр/валидатор в `scripts/` принимает JSON или CSV, проверяет данные относительно справочников из `lib/data.ts` и файловой системы, а затем выводит ошибки с номерами строк/товаров. Он не меняет сайт автоматически и не принимает тестовые данные в production-источник. Тесты импортёра будут использовать отдельные фикстуры с намеренно корректными и ошибочными примерами.

Фотографии будут размещаться в `public/images/products/<category>/<subcategory>/`. В данных хранятся публичные пути, а не внешние URL. В документации будут указаны требования: реальные фото магазина, понятное имя файла, JPG/PNG/WebP, сохранение пропорций, оптимизация до разумного размера и проверка на мобильном экране.

## Критерии готовности

- `products` остаётся пустым, пока не передан подтверждённый ассортимент.
- Валидный тестовый JSON/CSV проходит проверку, а фикстуры с дубликатами, неверными связями, ценой, единицей и фото дают понятные ошибки.
- Текущий каталог продолжает собираться без новых товаров.
- Проходят `npm run typecheck`, `npm run lint`, `npm test` и `npm run build`.
- Документация объясняет, какие файлы передать для первой категории «Домашние полуфабрикаты».
