# Поиск, фильтры и сортировка каталога

## Цель

Добавить для пустого, готового к наполнению каталога единую клиентскую систему поиска, совместных фильтров и сортировки без изменения маршрутов, архитектуры шести категорий и подтверждённых данных.

## Границы

- `products` и `productSlugs` остаются пустыми; публичные демонстрационные товары не добавляются.
- Реальная логика работает с существующей моделью `Product`, включая цену `null`, наличие, `purpose`, `characteristics` и `tags`.
- UI используется на общем каталоге, странице категории и странице подкатегории; подборки остаются отдельными маршрутами и вычисляются по ссылкам/назначениям после загрузки ассортимента.
- Supabase, админ-панель, корзина, оплата и новые зависимости не добавляются.

## Подходы

1. Чистый фильтр/сортировщик + локальное состояние React — выбран: совместим со статическим GitHub Pages, тестируем и не требует URL-состояния.
2. Фильтры в query-параметрах — отклонён для этого этапа: полезен для шаринга, но увеличивает scope без требования сохранять состояние ссылки.
3. Библиотека фильтрации — отклонена: существующей модели достаточно, новая зависимость не нужна.

## Решение

`lib/catalog-filters.ts` содержит типы состояния, нормализацию русскоязычного поиска, совместную фильтрацию, сортировку и вычисление доступных подкатегорий/подборок. `components/catalog-browser.tsx` отвечает за доступный responsive UI: desktop-панель и mobile drawer-подобную раскрываемую область. Тестовые fixtures находятся только в `lib/catalog-filters.test.ts`.

Цена `null` не участвует в диапазонных фильтрах и сортируется после товаров с ценой. Метки `popular` и `new` используются для сортировки, отсутствие метки не ломает порядок. Подборки формируются по `purpose`/`tags` и дедуплицируют товары по slug.
